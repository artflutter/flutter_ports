## Findings

### F1 (confirmed, low): a wrong line citation in the generator

`tool/reference/controller_radar_reference.mjs:85` says "The controller writes it (:95)" for the
`angle` property. At the pin, `controller.radar.js:95` is `y,`. The write
`angle: pointPosition.angle,` is at `:96`.

Probe: `sed -n 94,97p third_party/Chart.js/src/controllers/controller.radar.js` gives `x,`, `y,`,
`angle: pointPosition.angle,` and `skip: isNaN(x) || isNaN(y),`.

Fix: change `(:95)` to `(:96)`. Then rerun the generator: the comment is not in the data, thus
the data does not change.

### F2 (confirmed, low; the cause is outside the unit): the reset of a new point writes NaN where upstream writes `undefined`

`controller.radar.dart:201-202` writes `x: radial.xCenter` and `y: radial.yCenter` in the mode
`reset`, as `controller.radar.js:90-91`. Before the first layout of a radial scale, upstream
`xCenter` is `undefined`. The port gives NaN (`scale.radialLinear.dart:832`, "NaN stands for JS
`undefined`", and `double get xCenter` of `types.RadialLinearScale`, ADR 0028 §1). Upstream
writes `x: undefined`. The port writes `x: NaN`, and the element stores NaN, not the `undefined`
state.

The next animated update creates the animation of `x`. `core.animation.js:32` takes `from` from
`resolve([cfg.from, currentValue, to])`. Upstream skips the `undefined` value, thus `from` is
`to`. The port keeps NaN, thus `from` is NaN. The point is at NaN for the full animation.

How to get there: an existing radar controller gets a new radial scale and a new point in the
same `chart.update()`. For example, set `rAxisID: 'r2'` on the dataset, push one item, and call
`chart.update()` with animations on. `_insertElements` resets the new point before the layout
of the new scale.

Probes:

- `<scratch>/wave2/U-radar-review/xcenter_probe.mjs` (x64 Node.js, pinned build, animator
  stopped so the animation keeps its start state): the reset writes `x undefined`, `skip true`;
  after the update the `x` animation of point 3 goes from `25` to `25`.
- `<scratch>/wave2/U-radar-review/xcenter_probe_test.dart` (`flutter test` from
  `packages/flutter_chartjs`): the `x` animation of point 3 goes from `NaN` to `25.0`; after a
  pump of 500 ms, `point.x` is NaN.

Effect: during the animation, the port draws the new point and the line segment to it at NaN.
Upstream draws them at the final position. A `mousemove` hit test uses the current position,
thus the hit element can differ during the animation (Chart.js ADR 0009). No reference case or
test covers this path. `controller.polarArea.dart:361` reads `scale.xCenter` for its reset in
the same way.

Owner: the cause is the NaN start value of `RadialLinearScale.xCenter` and `yCenter` (phase 6)
and the `double` type of ADR 0028 §1, not the radar file. The radar code is a literal port. The
phase lead or W2-int decides: a nullable `xCenter` and `yCenter` (the `undefined` state), or a
`differences.md` row with a pin test.
